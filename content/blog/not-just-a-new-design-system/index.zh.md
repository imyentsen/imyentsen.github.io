# 目標

我們的任務是在推進新世代產品開發的同時，同步重構整套設計系統。這套產品原本是從 Aker Solutions 分拆出來、由約 40 個小應用程式組成的系統。在品牌重塑與產品重構的過程中，我們的目標是統一使用者體驗、汲取過去的經驗教訓，並解決過去沒有機會妥善處理的設計與技術債務。

# 我的角色

我是設計系統團隊中兩位設計師之一，負責約一半的 Token、元件與設計模式。我也與另一位設計師（團隊設計主管）密切協作，共同定義策略與工作方式。

# 挑戰

## 同步推進設計系統遷移與產品探索

![challenge.jpg](challenge.jpg)

挑戰來自於設計系統端與產品端的同步遷移。

- 設計系統理應以穩定產品探索為目標，節奏應相對緩慢。然而這個理想與我們的遷移現實相衝突——當產品團隊仍在進行新穎、探索性的設計時，很難打造出成熟的元件。使用情境持續變動，使元件的範疇難以收斂。
- 其次，我們需要沿用外部品牌顧問公司所制定的視覺規範。他們的規範視覺上相當精緻，但對可及性與元件架構的考量不足。我們必須在遵循新設計語言的同時，將其本地化至我們的產品脈絡中。


# 方法
## 以結構化交付支撐野性的產品探索

![approach1.jpg](approach1.jpg)

我們將交付項目分為三個層級：Token、元件與設計模式，以此定義各層的所有權與範疇，更有效率地支持快速的產品探索。

例如，當產品團隊需要為一套概念性使用流程建立元件，而設計系統元件尚未到位時，透過結構完善的 Token，他們仍能確保設計語言的一致性。此外，若我們日後決定將這套概念設計納入設計系統，預先指派的 Token 也能讓整合過程更快速、更透明。

## 縮小元件範疇

![approach2.jpg](approach2.jpg)

我們將關注焦點從使用情境轉移到設計形狀本身，不再針對每個情境打造客製化元件，而是讓元件保持精確且單純，將大型元件拆解為更小、更單純的基礎元件，並使其在使用情境上保持通用性。

## 改善治理機制與聯邦式貢獻

![approach3.jpg](approach3.jpg)

我們調整了工作流程——在品牌重塑期間，我們更主動、更具前瞻性。我們每週定期與設計師舉辦同步會議，事先準備主題、簡報、小型工作坊與討論題目，使這個活動成為一種新儀式，讓所有設計師了解設計系統的最新進展，並有機會貢獻意見，以更自然、更協作的方式推動新設計語言的採用與對齊。

各產品團隊需要快速建立自訂元件，同時遵守新設計語言。我們建立了一套流程與文件空間，讓他們能安全地在其中工作，並與其他團隊共享文件。提高文件透明度，也讓我們能更有效率地將他們的成果採納並內化到新設計系統中。

## 建立設計工具，讓團隊跑得更快

## 以 Vibe Coding 加速並擴大原型規模

![approach5.jpg](approach5.jpg)

數位孿生的特殊性質需要在 3D 模型檢視器和 2D 協作畫布上進行大量原型製作，而這在 Figma 中相當困難。我們提早採用了最新的 Figma Make 功能，以實現快速原型製作與高效的概念驗證。例如，我們將 Data Label 元件的設計交付縮短為 1 個衝刺（Sprint），相較於先前版本大幅提升效率。

我們與開發者密切協作，將提示詞拆解為細小且具體的步驟，以降低錯誤率，並防止 AI 探索無關的方向，確保設計師能得到更一致、更可重現的成果。此外，我們也建立了一套標準化提示詞，讓設計師能獨立建立 3D 測試樣板。

# 成果

這項重構工作在撰文當下仍在進行中。在一年的時間內，我們已建立：

- 全新的 Token 體系，涵蓋色彩、間距、字體排版、圓角、斷點等
- 文件框架
- 一套精簡的核心元件（約 25 個），可加速並統一進行中的 UX 探索
- 若干用於跨元件治理與特定使用情境的關鍵設計模式
- 一套定期設計審查與同步儀式，以呼應全公司的新工作方式

這次經歷再次印證了我的信念：一套成功的設計系統，絕不只是元件的集合，更關乎文化、溝通，以及為貢獻與迭代創造空間。
